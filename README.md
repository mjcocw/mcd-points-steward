## 💡 它解决什么问题

每个人账户里都躺着麦当劳积分，但几乎没人真的算过账：

- 账户里有一批积分**下个月就作废**，你没收到任何提醒
- 麦麦省的券躺在卡包里，**没人领、没人用**
- 商城里 1 积分到底能换几毛钱？抽一次奖**期望值是多少**？是不是纯玄学？

**McPoints Steward** 把这些一次性算清楚，输出一张**能直接截图发群**的资产体检报告。

一句话：**它不是帮你省钱的工具，是帮你把积分真正花出去的会计。**

## 🎯 三个别人不会算的东西

市面上已有的参赛项目大多停留在"帮你找券""帮你比价"。这个项目往后多走了三步：

### ① 个人边际效用折扣 —— 同一张券，对不同人价值不同

券上写「5 元」，但如果你本来就会花这 5 元买可乐，这张券对你的真实价值远不止 5 元；反过来，一张 50 元的周边你可能压根不想要。

所以每张券、每个奖品、每件商品都会乘一个**效用系数**：

| 对象 | 效用系数 | 理由 |
|---|---|---|
| 巨无霸套餐 | 1.00 | 招牌，而且本来就是你会买的东西 |
| 中可乐 | 0.25 | 你本来就会买可乐，这张券只是省了决策 |
| 5 元代金券 | 0.85 | 通用、立刻能抵扣 |
| 麦乐鸡（5 块） | 0.65 | 要真去吃才有价值 |
| 麦麦帆布袋 | 0.35 | 实物，喜好差异极大 |
| 谢谢参与 | 0.00 | 没有价值 |

**不建模这一层，所有"积分价值"的结论都是错的。**

### ② 抽奖期望值 + 方差 + 颗粒无收概率

从 `query-lottery-info` 拉下奖品池，逐项算概率、折算效用价值、求期望与标准差：

```
单次期望 4.96 元   标准差 8.42 元   颗粒无收概率 40%
每积分期望 0.0496 元  ←  是兑换名义汇率 (0.0100 元/分) 的 5.0 倍
```

标准差比期望值还大，说明抽奖是**高方差**选项。工具不会只给你一句"快去抽"，而是把**期望值和最差情况并排摆出来**让你自己选。

### ③ 三条路线量化对比 + 0/1 背包求解

不告诉你"应该怎样"，而是把三种花法都算到小数点后一位：

```
路线                    期望值      最差情况      积分用掉
稳健型：全部换成确定的商品      112.2元    112.2元      800分
平衡型：到期积分抽奖，长期积分兑换  122.2元    112.2元    1,000分 ←推荐
进攻型：积分全部拿去抽奖       162.8元    103.2元    1,200分
```

兑换商品的选择用 **0/1 背包**精确求解（积分离散化 + DP + 回溯），保证在积分上限内效用价值最大。

**最终推荐逻辑是可解释的**，不是拍脑袋：

> 你有 240 积分将在 30 天内过期，机会成本为零 —— 拿去抽奖的每积分期望值（0.0496 元）是兑换名义汇率（0.0100 元）的 5.0 倍，所以**「到期就抽、长期就换」**是期望值最高且风险可控的组合。

## 🚀 快速开始

### 三行命令跑起来（**不需要任何 Token**）

```bash
git clone https://github.com/<你的用户名>/mcd-points-steward.git
cd mcd-points-steward
python main.py --mock --html demo/report.html
```

零第三方依赖，Python 3.9+ 开箱即用。`--mock` 会加载一套完整的离线演示数据，
**评审者 clone 下来 10 秒就能看到完整效果**。

### 跑你自己的真实账户

**第 1 步**：到 [麦当劳 MCP 开放平台](https://open.mcd.cn/mcp) 用手机号登录 → 控制台 → 激活，申请 MCP Token。

**第 2 步**：在 WorkBuddy 里配置自定义连接器（左侧边栏 → 专家·技能·连接器 → 自定义连接器 → 配置 MCP）：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_TOKEN"
      }
    }
  }
}
```

> ⚠️ 记得把 `YOUR_MCP_TOKEN` 换成真实 Token。

**第 3 步**：跑起来

```bash
export MCD_MCP_TOKEN=你的Token       # Windows: set MCD_MCP_TOKEN=你的Token
python main.py --live --html my-report.html
```

### 其他用法

```bash
python main.py --mock --json result.json   # 导出结构化结果，方便二次开发
python main.py --live --horizon 60          # 把到期高危窗口放宽到 60 天
python selftest.py                          # 24 项自检，验证核心计算链路
```

## 🔌 用到的麦当劳 MCP 能力

| Tool | 用途 | 在本项目中的角色 |
|---|---|---|
| `query-my-account` | 积分账户总览：可用 / 累计 / 冻结 / **即将过期积分** | 资产盘点 + 到期预警的数据源 |
| `query-my-coupons` | 账户中已持有的优惠券 | 计算零成本收益，识别最先过期的券 |
| `available-coupons` | 麦麦省当前可领但未领的券 | 找出"0 成本白拿"的部分 |
| `mall-points-products` | 麦麦商城积分兑换商品清单 | 反推积分汇率 + 背包求解的物品池 |
| `query-lottery-info` | 积分抽奖活动奖品池、消耗规则、中奖概率 | 期望值 / 方差 / 颗粒无收概率计算 |
| `query-meals` | 当前门店在售菜单与价格 | 给"免费券"估算真实面值 |

调用流程与字段映射详见 [`MCP_INTEGRATION.md`](./MCP_INTEGRATION.md)。

## 🧮 计算原理

```
                      ┌──────────────────────┐
                      │  query-my-account     │──▶ 可用积分 / 即将过期积分池
                      └──────────────────────┘
                                 │
   ┌───────────────┬─────────────┼─────────────┬────────────────┐
   ▼               ▼             ▼             ▼                ▼
query-my-     available-   mall-points-   query-lottery-   query-meals
 coupons       coupons      products      info             (菜单价格)
   │               │             │             │                │
 券面值        可领券       积分汇率      期望值/方差      券面值估算
 解析        (0成本)      (中位数)      (效用加权)         (菜单价)
   │               │             │             │                │
   └───────────────┴──────┬──────┴─────────────┴────────────────┘
                           ▼
              ┌────────────────────────┐
              │  个人边际效用折扣模型    │  ← 本项目的核心
              │  价值 = 面值 × 效用系数  │
              └────────────────────────┘
                           ▼
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
    稳健型              平衡型              进攻型
  全部兑换           到期抽+长期换        全部抽奖
  (0/1背包)          (期望值最高)        (高方差)
        └──────────────────┼──────────────────┘
                           ▼
              期望值 / 最差情况 / 颗粒无收概率
                           ▼
              终端报告 + 单文件 HTML 报告
```

**关键取舍**：所有估值都乘了效用系数，所以报告里的"元"是**对你而言的价值**，不是标价。
这也是为什么同一套数据，工具会给出"中可乐只值 2.5 元"这种反直觉但正确的结论。

## 🛡️ 设计边界（诚实声明）

这个项目**不做什么**，和它**做什么**一样重要：

- **不下单、不付款、不动你的账户**。全程只读，唯一会写的是你手动点「一键领券」那一下。
- **不处理你的个人身份数据**。MCP Token 只从环境变量读取，绝不写进代码或配置文件。
- **所有估值是估算，不是官方口径**。面额来自接口返回值，效用系数是本项目公开的启发式参数，
  你可以按自己的偏好改 `valuation.py` 里的 `NAME_UTILITY` 表。
- **不构成任何消费建议**。餐品信息、价格与供应状态以麦当劳官方渠道实时结果为准。
- **接口字段名会变**。所有解析都走多候选键名 + 别名表，字段改名不会让项目崩掉；
  解析不出来的项会被计数并写进报告，而不是被静默吞掉。
