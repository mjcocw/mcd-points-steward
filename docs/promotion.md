**正文**：
```
官方 MCP 开放了积分账户、商城、抽奖三个接口，但榜单上几乎没人用。
我用它们做了个积分资产体检工具（只读，不下单不领券）。

几个可能对别人有用的实测结论：
- mall-points-products 的 price 字段对商品券恒为 0，真实面值藏在 spuName 里
- 50 件商品里 43 件已下架或非积分兑换物，必须按 downTime 过滤
- query-lottery-info 不返回中奖概率也不返回面值
- 官方把 Month 拼成了 Mouth（currentMouthExpirePoint）
- 业务错误是 HTTP 200 + {"success":false,...}，不抛异常
- query-meals 强制要 storeCode；query-nearby-stores 的 searchType=2 必须带 city+keyword

实现上零第三方依赖，Python 3.9+ 直接跑，40 项自检。
无 Token 也能跑（--mock 的字段结构和真实接口完全一致）。

GitHub：<你的仓库地址>
欢迎提 issue 补充你知道的接口细节。
```

## 六、评论区/Issue 回复话术（被提问时用）

**"这和 XX 省钱助手有什么区别？"**
> 省钱助手是帮你找券，我是帮你算「你手里的资产到底值多少、怎么花最优」。
> 举个例子：官方把即将过期积分放在 `currentMouthExpirePoint` 里（还把 Month 拼成了 Mouth），
> 没有任何一个省钱项目会去读它。我的工具会算清楚这批积分的期望值是拿去抽还是换。

**"概率官方都没公布，你的期望值靠谱吗？"**
> 不靠谱，所以我明说了。报告里写的是「官方未公布概率，按等概率假设（结果偏乐观）」，
> 并把「颗粒无收概率」显示为**未知**而不是 0%。工具的职责是把不确定性摊开给你看，不是替你拍板。

**"会不会下单/花钱？"**
> 不会。全程只读，`create-order` / `draw-lottery` / `auto-bind-coupons` 这些写接口我刻意没接。
> 唯一会动账户的是你自己手动点领券那一下。
